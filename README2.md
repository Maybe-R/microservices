# Домашнее задание к занятию «Микросервисы: подходы»
## Задание №1

Предложите решение для обеспечения процесса разработки: хранение исходного кода, непрерывная интеграция и непрерывная поставка. Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.

Решение должно соответствовать следующим требованиям:

облачная система;
система контроля версий Git;
репозиторий на каждый сервис;
запуск сборки по событию из системы контроля версий;
запуск сборки по кнопке с указанием параметров;
возможность привязать настройки к каждой сборке;
возможность создания шаблонов для различных конфигураций сборок;
возможность безопасного хранения секретных данных (пароли, ключи доступа);
несколько конфигураций для сборки из одного репозитория;
кастомные шаги при сборке;
собственные докер-образы для сборки проектов;
возможность развернуть агентов сборки на собственных серверах;
возможность параллельного запуска нескольких сборок;
возможность параллельного запуска тестов.
Обоснуйте свой выбор.

## Ответ

| Наименование | Краткое описание | Плюсы | Минусы |
|--------------|------------------|-----------|---------|
| GitLab CI/CD |  Единая DevOps‑платформа для автоматизации сборки, тестирования и развёртывания программного обеспечения  |  "Все в одном", минимальная интеграционная нагрузка, можно переиспользовать конфигурации, хорошая поддержка секретов, возможность разделение логического доступа к репозиториям и управлению | Привязан к экосистеме GitLab, продвинутые функции безопасности в платной версии |
| GitHub + GitHub Actions (Cloud) | Платформа, которая основана на системе контроля Git, с дополнительным использованием платформы непрерывной интеграции и непрерывной поставки  | Огромный маркетплейс готовых решений (тесты, сканы, деплои), Матричные сборки хорошо отрабатывают, поддерживает OIDC для безопасного доступа к облакам | Продвинутые функции безопасности можно использовать только через сторонние интеграции, высокая зависимость от конкретного вендора, жесткая привязка к экосистеме |
| Azure DevOps (Cloud) + Azure Repos/GitHub  | Связка позволяет объединить мощную платформу для управления разработкой с разными вариантами хранения кода | Гибкость в выборе системы контроля версий, мощный набор enterprise-функций для управления жизненным циклом разработки, YAML‑pipeline с параметрами и шаблонами покрывает сложные сценарии | Не интуитивно понятный интерфейс, меньше готовый решений, для мульти-облачных сценариев требуется дополнительная настройка |

Каждое из вышеописанных решений выполняет все требования. Данных для предложения одного решения недостаточно, все будет зависеть от того, что будет являться приоритетом. Если важная единая платформа с минимальной интеграционной нагрузкой - GitLab CI/CD, если важна скорость внедрения - GitHub Actions, а если важно выстроить строгий CI/CD-пайплайн с чётким разделением обязанностей, контролем доступа и безопасной передачей секретов - то это Azure.  

## Задания №2

Предложите решение для обеспечения сбора и анализа логов сервисов в микросервисной архитектуре. Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.

Решение должно соответствовать следующим требованиям:

сбор логов в центральное хранилище со всех хостов, обслуживающих систему;
минимальные требования к приложениям, сбор логов из stdout;
гарантированная доставка логов до центрального хранилища;
обеспечение поиска и фильтрации по записям логов;
обеспечение пользовательского интерфейса с возможностью предоставления доступа разработчикам для поиска по записям логов;
возможность дать ссылку на сохранённый поиск по записям логов.
Обоснуйте свой выбор.

## Ответ
| Наименование | Плюсы | Минусы |
|--------|--------|-------|
| Grafana Loki + Promtail/Alloy + Grafana | Масштабируемое хранение, при которых индексируются только метки, а логи сжаты, единый интерфейс, подходит как для простых локальных задач логирования (Promtail), так и когда нужна расширенная наблюдаемость (Alloy) | Плохой полнотекстный поиск, при пиковой нагрузке уменьшается гарантия доставки сообщений (требуется буфер) |
| Elastic Stack | Зрелый, проверенный стек с богатыми возможностями парсинга, мощный полнотекстовый поиск и аналитика, Kibana предоставляет продвинутые дашборды | Индексируется полное содержимое логов, сложнее масштабировать под большие объемы микросервисных логов, требует больше ресурсов и администрирования |
| Graylog + Sidecar (Filebeat/Winlogbeat) + Elasticsearch/OpenSearch | Удобный интерфейс "из коробки" для логов, централизованное управление агентами и конфигурациями, поддержка нескольких входов, парсеров, правил обработки и алертинга | Зависимость от Elasticsearch/OpenSearch , меньше экосистема и готовых интеграций по сравнению с Elastic/Grafana, при очень больших объёмах логов требуется тщательное планирование кластера и индексов |

Каждое из вышеописанных решений выполняет все требования. Конкретный выбор одного решения зависит от бюджета, назначение логов (простые алерты или нужно подробное описание с возможностью расследования инцидентов), а так же описание инфраструктуры, в которой должны собираться логи и квалификация специалистов. Самый дешевый и простой вариант - Grafana, если нужна максимальная аналитика и аудит - Elastic Stack, если удобный интерфейс, команда, которая будет это эксплуатировать, состоит из специалистов среднего класса и нужны только алерты - Graylog.

## Задание №3

Предложите решение для обеспечения сбора и анализа состояния хостов и сервисов в микросервисной архитектуре. Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.

Решение должно соответствовать следующим требованиям:

сбор метрик со всех хостов, обслуживающих систему;
сбор метрик состояния ресурсов хостов: CPU, RAM, HDD, Network;
сбор метрик потребляемых ресурсов для каждого сервиса: CPU, RAM, HDD, Network;
сбор метрик, специфичных для каждого сервиса;
пользовательский интерфейс с возможностью делать запросы и агрегировать информацию;
пользовательский интерфейс с возможностью настраивать различные панели для отслеживания состояния системы.
Обоснуйте свой выбор.

## Ответ

| Наименование | Краткое описание | Плюсы | Минусы |
|--------|--------|-------|----------|
|Prometheus + Node Exporter + cAdvisor + Grafana | Node Exporter на каждом хосте — собирает метрики ресурсов хоста, cAdvisor — собирает метрики по каждому контейнеру/сервису, Prometheus — центральный сервер, Grafana — UI для запросов | Богатая экосистема, Grafana даёт гибкие запросы, агрегации, настраиваемые панели и шаблоны, полностью покрывает требования | «Чистый» Prometheus плохо масштабируется на очень большие кластеры, требуется развёртывания нескольких компонентов |
| VictoriaMetrics (single или cluster) + vmagent/vmalert + Grafana | vmagent собирает метрики, VictoriaMetrics хранит метрики, а Grafana выполняет роль удобного интерфейса | При больших объемах требуется не так много ресурсов, встроенная поддержка долгосрочного хранения и кластеризации, полная совместимость с Grafana - те же дашборды и запросы, что и для Prometheus | Меньше «официальной» документации и готовых интеграций, алертинг необходимо дорабатывать, сложнее найти готовые решения под узкие кейсы |
| Grafana Mimir + Prometheus + Grafana| Mimir выполняет долгосрочное хранение, Prometheus — центральный сервер, агенты которого стоят на каждом хосте, Grafana выполняет роль единого интерфейса для запросов и дашбордов | Масштабируемость на сотни/тысячи нод и долгосрочное хранение, сохраняется вся экосистема Prometheus | Неудобно эксплуатировать, необходимо администрировать mimir кластер, больше точек отказа, требуется зрелая команда для поддержки |

Каждое из вышеописанных решений выполняет все требования. К сожалению в требованиях не указан самый явный показатель при выборе - масштаб, число хостов, сервисов, желаемый срок хранения. Если требуется обработка средних объемов и быстрое развертовывание - Prometheus + Node Exporter + cAdvisor + Grafana, если требуется обработка больших кластеров, а с ресурсами "плохо" - VictoriaMetrics (single или cluster) + vmagent/vmalert + Grafana, если масштаб большой, эксплуатировать будут продвинутые специалист ИТ, требования по хранению и доступности в компании жесткие  -  Grafana Mimir + Prometheus + Grafana.
