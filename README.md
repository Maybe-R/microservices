# Домашнее задание к занятию «Микросервисы: принципы»

## Задание 1
Предложите решение для обеспечения реализации API Gateway. Составьте сравнительную таблицу возможностей различных программных решений. На основе таблицы сделайте выбор решения.

Решение должно соответствовать следующим требованиям:

маршрутизация запросов к нужному сервису на основе конфигурации,
возможность проверки аутентификационной информации в запросах,
обеспечение терминации HTTPS.
Обоснуйте свой выбор.

## Ответ
 | Наименование | Краткое описание | Плюсы | Минусы |
|----------|----------|----------|----------|
| NGINX   | Позиционируется как стандартное решение среди выбора веб-серверов, но за частую используется как API Gateway во многих компаниях из-за своих плюсов | Быстрый и эффективный по потреблению памяти, держит высокие нагрузки, гибкий в настройке маршрутизации, очень быстрая поддержка SSL/TLS | В бесплатной версии возникает сложность реализации проверки токенов, по этому требует разработки и поддержки отдельного микросервиса |
| Traefik | Программный маршрутизатор в облачных инфраструктурах, который специально создали для микросервисов | Самостоятельно находит сервисы, имеет встроенную поддержку Let's Encrypt, удобный веб-интерфейс, потребляет мало памяти | В бесплатной версии поддерживается Basic Auth и ForwardAuth, плохо выдерживает высокие нагрузки, мало плагинов для трансформации запросов или сложного логирования |
| Kong | Построено на базе NGINX и OpenRestry, работает как обратный прокси | Есть очень много плагинов, которые облегчают работу, гибкая настройка маршрутизации, есть готовые интеграции с мониторингом, например с Prometheus | Зависит от БД, что усложняет эксплуатацию, потребляет больше памяти, продвинутые функции в платной версии  |
| Spring Cloud GW | Ориентировано на Java-разработчиков. Не является отдельным сервером, а библиотека, которая встраивается в SpringBoot Приложение | Идеальная интеграция с Java-стеком, возможность реализации любой логики запросов, недоступную в стандартных шлюзах, хорош в асинхронных сценариях и поддерживает высокую нагрузку | Не является коробочным решением, по этому требует разработки, неудобная терминация HTTPS на границе сети, потребляет много памяти и может долго "думать", требует дополнительных знаний Java |

Вводных данных, для точного выбора, крайне мало, так как нет описания какая квалификация у эксплуатационного персонала, на какой бюджет необходимо ориентироваться (возможность использовать платные версии), какое окружение будет в инфраструктуре, точность в требованиях по аутентификации и т.п. Так как по всем вышеуказанным параметрам подходят все 4 рассмотренных решения. 
Свое личное предпочтение отдам NGINX, так как его знают как DevOps-инженеры, так и начинающие ИТ-специалисты, он проверен временем и зарекомендовал себя максимально надежным.

## Задание №2

Составьте таблицу возможностей различных брокеров сообщений. На основе таблицы сделайте обоснованный выбор решения.

Решение должно соответствовать следующим требованиям:

поддержка кластеризации для обеспечения надёжности,
хранение сообщений на диске в процессе доставки,
высокая скорость работы,
поддержка различных форматов сообщений,
разделение прав доступа к различным потокам сообщений,
простота эксплуатации.
Обоснуйте свой выбор.

## Ответ 
 | Наименование | Краткое описание | Плюсы | Минусы |
|----------|----------|----------|----------|
| Apache Kafka | Распределенная платформа потоковой передачи событий, ставшая стандартом для высоконагруженных систем | Высочайшая пропускная способность, надежное хранение данных, которое позволяет просматривать историю событий и восстанавливать состояние, горизонтальное масштабирование при помощи брокеров, имеет огромное количество коннекторов, имеет готовые клиенты, интегрируется с мониторингом, поддерживает SSL/TLS шифрование, гибкие ACL на уровне тем и групп пользователей | Относительно не прост в эксплуатации, новичкам не подойдет, потребляет много памяти и дискового пространства, не подходит для сценариев реального времени | 
| Redpanda | Позиционируется как «Kafka без JVM и ZooKeeper», обеспечивая полную совместимость с клиентами Kafka | Простой в эксплуатации, идеально для Kubernetes и Docker, Высокая производительность, быстрее чем у Kafka, очень много бесплатных функций, Поддерживает mTLS, SASL, ACL аналогично Kafka | Мало статей по данному решению, можно использовать только как внутреннее решение (проблемы с лицензированием), требовательна к дискам |
